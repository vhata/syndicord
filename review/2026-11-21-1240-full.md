## Summary

Six findings remain open: one P1, two P2, and three P3. Four are new:
relative entry links can inherit private feed credentials, malformed XML
can consume quadratic CPU before validation, older populated installations
lose their webhook configuration during the web-admin upgrade, and repeated
requests can prolong an authentication cooldown. Atom MIME content rendering
and packaged documentation links remain open from the previous review.

Three previous findings are verified fixed: direct feed source/fallback links,
HTML cleanup complexity, and package-test Git isolation. The two new feed
findings have different triggers from the fixed cases and receive separate
identities. No product fixes are included in this snapshot.

## Findings

### Open and Moved

- `relative-entry-links-inherit-feed-credentials` — **Relative entry links publish credentials inherited from the configured feed URL.** Security · Open · Verified.
  - Where: `src/feed.ts:115` (`safeLink`, URL resolution at line 118), and `src/discord.ts:113`–115 (`buildMessage`).
  - Severity: P1.
  - An RSS entry containing only `<link>#post</link>` resolves against `https://example.test/feed?token=SYNTHETIC_PRIVATE_QUERY_TOKEN`, and the token-bearing URL plus fragment becomes the Discord title link. The equality guard rejects only the exact configured URL; path credentials also survive `#post` and `./post`. The entry supplied no credential: URL resolution introduced it. Preserve provenance or use a safe public base for presentation links, including fragment and path-relative cases, without unintentionally changing stored entry identities.
  - Review backlog: `protect-relative-entry-links`

- `quadratic-xml-prevalidation` — **Rejected XML can consume quadratic CPU before validation.** Performance · Open · Verified.
  - Where: `src/feed.ts:308` (`parseFeedDocument`, comment/CDATA removal).
  - Severity: P2.
  - Repeated unterminated `<!--` or `<![CDATA[` openers cause the unanchored expression to rescan the remaining input at each opener before XML validation rejects it. A 240,000-byte comment probe, below the 256 KiB fetch limit, consumed approximately 1.39 seconds of local CPU; the isolated expression accounts for essentially all of it. Replace preprocessing with a forward scan and cover malformed rejected documents in scaling tests. This establishes algorithmic cost, not a hosted CPU-limit measurement.
  - Review backlog: `bound-xml-prevalidation`

- `legacy-webhook-configuration-upgrade` — **Upgrading a populated pre-web-admin installation stops delivery.** Bug · Open · Verified.
  - Where: `migrations/0004_web_admin.sql:1`, `src/admin-store.ts:249` (`readRelayConfiguration`), and `docs/SETUP.md:134`–139.
  - Severity: P2.
  - Earlier installations store routes in D1 and webhook URLs in the `WEBHOOKS` Worker secret. Migration 0004 leaves `encrypted_webhooks` null, and the current runtime then loads those routes with an empty webhook map despite the retained secret, failing with `Missing webhook for destination updates`. Neither deployment nor migration imports that map or prevents the incompatible update; the documented update flow promises configuration preservation. Provide a validated import/transition path or fail deployment with actionable preparation instructions before replacing the working runtime. Fresh installations and installations already configured through web administration are unaffected.
  - Review backlog: `preserve-webhooks-during-admin-upgrade`

- `authentication-cooldown-slides-on-retry` — **Requests during a cached Discord cooldown postpone its expiry.** Bug · Open · Verified.
  - Where: `src/admin-auth.ts:460`–482 (`checkSession`).
  - Severity: P3.
  - A cached cooldown throws a rounded-up remaining `Retry-After`, then the catch block writes `Date.now() + retryAfter` as a new deadline, just as it does for a fresh provider response. After one mocked two-second 429, ten requests spaced 500 ms apart all still report two seconds, even after Discord recovers; no provider request is retried and the deadline remains two seconds ahead. Keep the existing absolute deadline for locally cached failures and update it only from a new provider 429. Waiting for the advertised delay without retrying does recover.
  - Review backlog: `preserve-authentication-cooldown-deadline`

- `atom-content-mime-html` — **Atom HTML content declared using MIME types is displayed as literal markup.** Bug · Moved · Verified.
  - Where: `src/feed.ts:370`–375 (`parseFeedDocument`); identity normalization also uses `atomText` at line 105.
  - Severity: P3.
  - The original fixture still yields `Hello world.` for `type="html"` and `<p>Hello <b>world</b>.</p>` for `text/html` and `application/xhtml+xml`. The code recognizes the short Atom content names but not these MIME forms. Normalize supported HTML MIME types while preserving plain-text semantics and fallback identities. The original reproduction and content-model reference remain in the previous snapshot.
  - Review backlog: `normalize-atom-html-mime-content`

- `installed-package-documentation-links` — **Shipped documentation references files absent from the npm package.** Docs · Moved · Verified.
  - Where: `package.json:62` (`files`), `README.md:2`, `docs/QUALITY.md:4`, and `docs/QUALITY.md:131`.
  - Severity: P3.
  - An offline npm pack manifest contains the README and quality guide but omits `assets/syndicord.svg`, `docket/CONTRACT.md`, and `review/README.md`, so those local references fail in an installed package. Use hosted repository links or ship the intended targets. This is the same packaging issue as the prior review; operator commands remain usable.
  - Review backlog: None; retain as inventory for the next documentation/packaging change.

### Relative links and XML cost

```sh
node --input-type=module <<'JS'
import { parseFeedDocument } from './src/feed.ts';
import { buildMessage } from './src/discord.ts';
const xml = '<rss version="2.0"><channel><title>News</title>' +
  '<item><guid isPermaLink="false">one</guid><title>One</title>' +
  '<link>#post</link></item></channel></rss>';
for (const url of [
  'https://example.test/feed?token=SYNTHETIC_PRIVATE_QUERY_TOKEN',
  'https://example.test/SYNTHETIC_PRIVATE_PATH_TOKEN/feed',
]) {
  const feed = await parseFeedDocument(xml, url);
  console.log(buildMessage(feed.entries[0], url).embeds[0].url);
}
for (const bytes of [16000, 32000, 64000, 128000, 240000]) {
  const before = process.cpuUsage();
  try {
    await parseFeedDocument('<!--'.repeat(bytes / 4), 'https://example.test/feed');
  } catch (error) {
    const cpu = process.cpuUsage(before);
    console.log(bytes, (cpu.user + cpu.system) / 1000, error.message);
  }
}
JS
```

Both emitted links contain the configured synthetic credential and `#post`.
Replacing the entry link with `./post` also inherits the secret path directory.

| ----------- | ------------------ | --------------------- |
| 16,000      | 6.8                | 6.8                   |
| 32,000      | 25.0               | 25.0                  |
| 64,000      | 99.9               | 99.0                  |
| 128,000     | 393.7              | 419.4                 |

### Authentication cooldown and populated upgrade state

This uses temporary local D1 and mocked Discord responses. Local runtime
processes need loopback access. The inserted configuration row is the state
produced when migration 0004 is applied to a populated earlier database.

```sh
node --input-type=module <<'JS'
import { createTestDatabase } from './test/helpers/d1.ts';
import { authEnv, browserLogin, discordFixture } from './test/helpers/auth.ts';
import { requireAdmin } from './src/admin-auth.ts';
import { readRelayConfiguration } from './src/admin-store.ts';
const { db, dispose } = await createTestDatabase();
const env = authEnv(db);
const originalNow = Date.now;
try {
  const options = { status: 200, retryAfter: '2', calls: [] };
  const fetcher = discordFixture(options);
  const { cookie } = await browserLogin(env, fetcher);
  const request = () => new Request('https://syndicord.example/admin', {
    headers: { Cookie: cookie },
  });
  let now = originalNow();
  Date.now = () => now;
  options.status = 429;
  await requireAdmin(request(), env, fetcher).catch(() => {});
  options.status = 200;
  const calls = options.calls.length;
  for (let i = 0; i < 10; i++) {
    now += 500;
    await requireAdmin(request(), env, fetcher)
      .catch(error => console.log(error.status, error.retryAfter));
  }
  console.log('New provider calls:', options.calls.length - calls);
  Date.now = originalNow;
  await db.prepare(
    'INSERT INTO relay_configuration (id, feeds, updated_at_ms) VALUES (1, ?, 1)',
  ).bind(JSON.stringify([
    { url: 'https://example.test/feed', destinations: ['updates'] },
  ])).run();
  await readRelayConfiguration({
    ...env,
    WEBHOOKS: JSON.stringify({
      updates: 'https://discord.com/api/webhooks/123/synthetic-token',
    }),
  }).catch(error => console.log(error.message));
} finally {
  Date.now = originalNow;
  await dispose();
}
JS
```

Actual result: ten `429 2` responses, zero new provider calls, and
`Missing webhook for destination updates`. At main commit `f9833b9`,
`src/index.ts` reads that same `WEBHOOKS` secret alongside stored D1 routes;
the current runtime has no such import or fallback.

An additional two-destination probe compared the historical parser with the
current scheduled Worker: the former accepted the retained mapping, and the
latter failed before polling. Adding just one missing webhook through the
editor's single-webhook operation also failed because the other route remained
unconfigured. Importing the complete mapping atomically restored usable relay
configuration; no delivery-history reset was required.
