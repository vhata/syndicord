## Summary

Five confirmed findings remain open: one P1, two P2, and two P3.
The highest priority is disclosure of private feed access tokens through
Discord source links. HTML cleanup has quadratic CPU behavior on small,
valid XML feeds, and a package-test fixture can modify the wrong Git
repository when Git environment selectors are inherited. Two smaller
findings concern Atom content rendering and installed documentation.

The relay/state pass found no actionable defect. Additional local D1
probes confirmed that lease loss during a fetch prevents ingestion and
sending, preserves the successor's lease and successful health timestamps,
and reports an expired unfinished run as degraded. An explicit empty
configuration disables polling without requiring webhook secrets.

## Findings

### Open

- `feed-credential-source-links` — **Discord source links expose private feed access tokens.** Security · Open · Verified.
  - Where: `src/discord.ts:92`, `src/discord.ts:106`, and `src/discord.ts:109` (`buildMessage`); accepted URL input at `src/config.ts:15`.
  - Severity: P1.
  - Every message copies the complete configured feed URL into its author link, including reusable tokens in query parameters or paths. This occurs even when the entry has a separate public link; entries without a link also use the private feed URL as their title link. Synthetic payloads reproduced both token forms. Use an explicit public source URL, a safe origin, or no source hyperlink; removing query parameters alone does not protect token-bearing paths. Priority reflects repeated credential disclosure, not a claim that any live credential was inspected or exposed during this review.
  - Review backlog: `protect-feed-access-urls`

- `quadratic-feed-html-cleanup` — **Unterminated HTML tags cause quadratic CPU work inside valid feeds.** Performance · Open · Verified.
  - Where: `src/feed.ts:27` (`text`), invoked for RSS descriptions at `src/feed.ts:275`.
  - Severity: P2.
  - Valid RSS containing a stable GUID and CDATA with repeated `<a` text makes the tag-removal expression rescan the remaining string at every candidate opening tag. The 16/32/64 KiB probes below consumed roughly 55/172/687 ms of local process CPU, all well below the 256 KiB input limit. The isolated expression accounts for almost all the cost; Feedsmith parsing alone took about 1 ms. Use linear-time cleanup and adversarial scaling coverage. These measurements establish local algorithmic behavior, not hosted CPU headroom.
  - Review backlog: `bound-feed-html-cleanup`

- `package-test-inherits-git-selectors` — **The Git-installation test can commit into its caller's repository.** Tooling · Open · Verified.
  - Where: `test/package-acceptance.ts:271` (inherited environment), `test/package-acceptance.ts:289` (subprocess execution), and `test/package-acceptance.ts:323` (fixture Git operations).
  - Severity: P2.
  - The fixture inherits Git-local environment variables before running `git init`, `git add --all`, and `git commit`. An inherited `GIT_DIR` can redirect those operations from the fixture to the caller's repository; a disposable reproduction changed a sibling repository's HEAD and replaced its tracked tree with fixture content. Clear the variables reported by `git rev-parse --local-env-vars` for fixture Git and npm processes, and verify isolation with hostile selectors. The project's current hooks do not run this suite; the trigger is an enclosing hook, wrapper, or explicitly configured Git environment.
  - Review backlog: `isolate-package-test-git-state`

- `atom-content-mime-html` — **Atom HTML content declared using MIME types is displayed as literal markup.** Bug · Open · Verified.
  - Where: `src/feed.ts:305` and `src/feed.ts:306` (`parseFeedDocument`); related identity normalization at `src/feed.ts:41` (`atomText`).
  - Severity: P3.
  - The application recognizes `html` and `xhtml`, but not `text/html` or `application/xhtml+xml` content. Conforming fixtures retain `<p>Hello <b>world</b>.</p>` and produce visible angle-bracket markup in the outbound excerpt; the `html` form produces `Hello world.`. Feedsmith preserves the MIME type correctly. Normalize supported HTML MIME content while preserving plain-text semantics and existing fallback identities. These content models are defined in [RFC 4287 sections 4.1.3.1 and 4.1.3.3](https://www.rfc-editor.org/rfc/rfc4287.html#section-4.1.3.1).
  - Review backlog: `normalize-atom-html-mime-content`

- `installed-package-documentation-links` — **Shipped documentation references files absent from the npm package.** Docs · Open · Verified.
  - Where: `package.json:59` (`files`), `README.md:2`, `docs/QUALITY.md:4`, and `docs/QUALITY.md:134`.
  - Severity: P3.
  - An offline package-manifest check confirmed missing targets for the README logo (`assets/syndicord.svg`), the quality guide's Docket contract, and its review index. The package ships the referring documents but omits `assets/`, `docket/`, and `review/`. Use hosted links for repository-only material or include the relevant assets. Operator commands remain usable; this is documentation packaging polish.

## Reproduction evidence

All examples use synthetic tokens and reserved example domains. Feed and
payload probes make no HTTP requests.

For the credential finding, run from the reviewed checkout:

```sh
node --input-type=module <<'JS'
import { buildMessage } from './src/discord.ts';
const entry = {
  id: 'id:1', title: 'Entry', description: 'Hello',
  link: 'https://example.test/public-post', publishedAt: null,
};
for (const feed of [
  'https://example.test/feed?token=SYNTHETIC_PRIVATE_TOKEN',
  'https://example.test/SYNTHETIC_PRIVATE_TOKEN/feed',
]) console.log(JSON.stringify(buildMessage(entry, feed)));
JS
```

Both payloads contain the token in `embeds[0].author.url`, despite the
entry's public URL. Setting `entry.link` to `null` also exposes it in
`embeds[0].url`.

For the CPU finding, the following produces valid RSS and measures only
local processing. Exact timings vary by machine:

```sh
node --input-type=module <<'JS'
import { parseFeedDocument } from './src/feed.ts';
const rss = (body) => `<rss version="2.0"><channel><title>News</title><item><guid isPermaLink="false">id1</guid><description><![CDATA[${body}]]></description></item></channel></rss>`;
await parseFeedDocument(rss('warmup'), 'https://example.test/feed');
for (const size of [8000, 16000, 32000]) {
  const xml = rss('<a'.repeat(size));
  const before = process.cpuUsage();
  await parseFeedDocument(xml, 'https://example.test/feed');
  const cpu = process.cpuUsage(before);
  console.log(Buffer.byteLength(xml), (cpu.user + cpu.system) / 1000);
}
JS
```
